Random, overlap và snapshot

Mỗi batch sinh đề có thể tái lập, giải thích nguồn pool và không thay đổi lịch sử khi ngân hàng được sửa.

← Hồ sơ Phase 0PoolRandomSnapshotAn toàn

Pool hợp lệ

Query trực tiếp question theo APPROVED, category/field active, đúng field+cognitive, cognitive_verified_at IS NOT NULL và source filters. Candidate ID được sort tăng dần trước shuffle.

Pool checksum là SHA-256 của algorithm version, config version, source filters và chuỗi ID + updatedAt của candidate theo thứ tự ổn định.

Random xác định

  • Batch có masterSeed; mỗi mã đề dùng seed dẫn xuất từ masterSeed + variantIndex bằng hàm hash có version.
  • Chọn không hoàn lại trong một paper và loại trùng question family/paraphrase.
  • Mặc định cho phép overlap giữa các mã đề; response hiển thị số/tỷ lệ overlap.
  • Nếu admin yêu cầu zero-overlap, availability từng cell phải ≥ count × variantCount.
  • Không mượn câu từ field/cognitive khác khi thiếu.

Snapshot bắt buộc

NhómDữ liệu
QuestionSource ID, stem, A–D, correct answer, explanation, option order, position
TaxonomyCategory và field ID/code/name; cognitive code/label
ProvenanceDocument ID/code/title/hash hoặc legacy source string
GenerationConfig version, algorithm version, seed, pool checksum, generatedAt/by

Attempt và report đọc snapshot, không join tên taxonomy live để diễn giải lịch sử.

Transaction và idempotency

  • Generate và assign bắt buộc idempotency key có unique constraint.
  • Cùng key + cùng request hash trả kết quả cũ; cùng key + payload khác trả conflict.
  • Pool checksum đổi sau preview trả conflict và yêu cầu preview lại.
  • Một cell thiếu hoặc snapshot lỗi rollback toàn batch; paper chỉ ở DRAFT.
  • Publish là quyền/transaction riêng; generation không tự publish hoặc assign.
